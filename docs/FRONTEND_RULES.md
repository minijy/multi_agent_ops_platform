# SellerForge 前端专用规则

> 本文档是 [ENGINEERING_RULES.md](ENGINEERING_RULES.md) 的前端专项补充。适用于 `frontend/index.html`、`frontend/app.js`、`frontend/styles.css` 以及所有新增前端模块。

## 1. 前端的责任边界

1. 前端负责展示、交互、本地暂存和用户反馈，不负责做最终权限判定、数据范围裁决或业务统计计算。
2. 服务端是会话、任务、权限、Connection、记忆和知识库状态的真实源。`localStorage` 只能保存主题、折叠状态、未发送草稿等非权威信息。
3. 页面隐藏不是权限控制。即使界面不展示某个按钮，API 仍必须在服务端校验身份。
4. 前端不得通过隐式默认值掩盖未配置状态。未配置模型、Connection 或知识空间时，应显示空状态和明确的下一步。

## 2. 角色和菜单可见性

1. 管理界面必须使用统一的角色允许机制，不得在多个渲染函数里零散判断 `role === 'admin'`。
2. 普通非 admin 用户不显示：
   - 运行概览。
   - 审批中心，除非用户是明确的 approver。
   - 连接器、用户与权限、审计日志和系统设置。
   - Agent、Skill、Tool 和租户记忆的管理操作。
3. 普通用户可访问长期记忆页，但页面只能展示当前用户的记忆、来源、偏好设置和删除/导出操作。租户策略、组织记忆和其他用户数据不得出现。
4. 对应业务 Tool 不可用时，依赖该 Tool 的专业 Analyst 不得出现在 Agent 列表、委派候选或模式说明中。
5. 权限变更或重新登录后，必须重新获取当前主体和可见资源，并清理上一身份的页面缓存。

## 3. 信息架构和页面形态

1. 列表页默认展示列表、状态、搜索和“新增”按钮，不得常驻展示大面积新增/编辑表单。
2. 新增、编辑、重置密码、绑定 Connection 等低频操作使用抽屉或对话框；抽屉关闭后必须重置草稿、错误和加载状态。
3. 配置流程必须按业务依赖顺序展示。例如：

   `创建 Connection -> 验证连接 -> Tool 选择 Connection -> 权限组授权 Tool -> Agent 可用`

4. 空状态必须同时说明当前情况和下一步操作，不得只显示“暂无数据”。
5. 不得在同一页重复展示两套表达同一状态的队列、Tool 列表、权限列表或配置卡片。

## 4. 表单与数据建模

1. 表单控件必须直接反映真实关系：
   - 一对一用单选。
   - 一对多用可增加的重复项。
   - 多对多用可多选下拉框、检查列表或可搜索多选器。
2. 权限组的 Tool 授权必须在权限组卡片/编辑抽屉中可多选。规则明细只读，不得提供“移动到权限组”。
3. 多选结果必须在界面内去重，但不得全局排除已被其他权限组选择的 Tool；同一 Tool 可被多个组授权。
4. 编辑现有对象时，密钥字段默认为空并显示“已配置，留空保持不变”。不得将脱敏占位符作为新密钥提交。
5. 表单提交期间禁用提交按钮，防止重复写入；成功后关闭表单并刷新对应列表，失败后保留用户已填内容。
6. 表单前端验证与 API Schema 保持一致，但不得依赖前端验证代替服务端校验。
7. 用户 ID、tenant ID、Connection ID 等稳定标识和显示名必须分开。列表主标题优先展示显示名，详情或辅助信息再展示 ID。

## 5. 对话与任务状态机

1. 前端必须以 `session_id`、`turn_id`、`task_id`、`tool_call_id` 为稳定 key，不得以文案、事件顺序或列表下标判断是否为同一任务。
2. 子任务在界面中是一个持续更新的节点：

   `queued -> running -> completed | failed | cancelled`

   收到 `running` 事件时更新已有 `queued` 节点，不得追加第二张卡片。
3. Tool 调用卡片、子 Agent 任务卡片和最终答案是不同层次；不得因为 `delegate_specialists` 完成就将整个对话标记为完成。
4. 只有收到并持久化最终 assistant message 或明确的 turn 终态时，才可显示全局“完成”提示。
5. 对话执行中，发送按钮应切换为“中断”；任务已中断且存在检查点时，显示“继续”。不得仅显示一个不可操作的“处理中”按钮。
6. 中断后立即停止打字效果和无限加载状态；恢复后从服务端事件序号继续，不得重放全部历史事件。
7. 同一事件被 SSE 重连或轮询重复返回时，必须根据事件 ID/序号幂等去重。
8. 执行超时、Token 预算超限、权限拒绝、子任务失败和用户中断必须是不同的终态和文案。

## 6. 会话列表与恢复

1. 会话列表必须从服务端按当前 `tenant_id + user_id` 加载，不得仅依赖浏览器 `localStorage`。
2. 切换账户、tenant 或退出时必须清空内存中的会话、任务和缓存，防止上一身份的数据短暂闪现。
3. 历史会话暂时缺少 owner 字段时，前端不得自行丢弃；应显示服务端返回的兼容结果，并由后端完成归属迁移。
4. 新建会话必须是明确的本地草稿状态；首次发送成功并获得服务端 `session_id` 后再置为持久化会话。
5. 删除会话成功后才从界面移除；服务端删除失败时不得伪装成功。
6. 后台任务列表必须跟随当前会话或显式标记为“全部任务”，不得把其他会话的任务混入当前进度。

## 7. 用户文案与技术详情

1. 默认文案回答三个问题：正在做什么、当前结果是什么、是否需要用户操作。
2. 不得在默认用户视图中直接显示：
   - 表名、SQL、DSN、Collection 名和内部字段。
   - Tool Schema、委派 JSON 和子会话 ID。
   - “紧凑结果”、“计算口径”、“上下文窗口”等实现语言。
3. 技术详情应放在默认收起的“查看执行详情”中，且仅向有权限的角色展示。
4. 数据结果需显示人类可读的来源名称，例如“领星利润报表”，不展示 `lingxing_profit_order_transactions`。
5. 用户无权时文案要说明“你当前没有某数据权限”和处理方式，不得让用户联系一个界面上不可见的专业 Analyst。
6. 回答中的有序列表必须渲染为单个语义化 `<ol>` 下的多个 `<li>`，序号交给浏览器计算。不得将每个 Markdown 列表项分割成独立 `<ol>`，否则会全部显示为 `1.`。
7. Markdown 表格、代码块、列表和段落必须分别做完整结构解析，不得用相互冲突的正则表达式连续替换 HTML。

## 8. 错误、加载与反馈

1. API 错误必须优先读取结构化 `detail.message`、`detail.hint` 和字段级验证错误，不得统一显示“出错了”或“请求失败 (500)”。
2. 401 需区分 Token 过期和账号失效；403 需展示缺失的权限；404 需区分资源已删除和路由未实现；409 需展示冲突处理方式；422 需定位到具体表单字段。
3. Toast 用于短暂成功或可恢复错误；需要用户操作的错误使用页内提示或对话框，不得只在数秒后消失的 Toast 中展示。
4. 同一操作不得同时弹出 Tool 成功、子任务成功和主任务成功三个重复 Toast。
5. 列表加载时保留当前内容并显示局部加载状态；只有身份切换时才应立即清空敏感内容。
6. 后台轮询必须在页面离开、身份退出或任务进入终态后停止，避免对不存在的 API 持续发起 404 请求。

## 9. Tool、Connection 和 Agent 页面

1. Tool 页只显示 Tool 能力、风险和已绑定的 Connection；连接凭证必须在 Connection 页管理。
2. Connection 列表必须区分“已启用”、“配置完整”、“连通”和“已被 Tool 引用”，不得统一显示为“运行中”。
3. 编辑 Connection 时根据类型只显示相关字段，不得让 Qdrant、Milvus、MySQL、PostgreSQL、钉钉等共用一套含大量无关输入的表单。
4. Agent 页的“通用 Analyst”和“并行专业 Analyst”必须是明确的运行模式开关，并显示并行上限 3。
5. 保留通用 Analyst 卡片，但专业 Analyst 只显示当前用户有权使用的部分。
6. Tool 选择器不展示系统基础 Tool；这些 Tool 在运行时默认可用，页面可以在说明区以“系统能力”展示，但不可编辑。

## 10. 模型与多模态交互

1. 对话发送前必须确认当前选中模型已启用、已配置 Key 且支持 Tool Calling。不满足时阻止发送并链接到模型配置。
2. 图片按钮只在 `supports_image=true` 时可用；语音按钮只在 `supports_audio=true` 时可用。
3. 用户切换到不支持附件的模型时，不得静默丢弃已选附件；必须说明将被移除的内容并让用户确认或明确提示。
4. 未配置 API Key 的模型卡片必须显示“未配置”，不得显示可选且不得依赖后端环境变量隐式调用。
5. 密码管理器自动填充的内容不得被当作 API Key 提交；密钥输入应使用合适的 `autocomplete` 和明确的用途标记。

## 11. 知识库与长期记忆页

1. 知识库页必须先展示知识空间/分类树，再展示文档和片段内容，不得只显示向量 Collection 和 Point 数。
2. 文档列表至少显示标题、分类、来源、处理状态、版本和更新时间；片段详情必须显示来源定位和元数据。
3. 未配置向量 Connection 时显示“前往连接器”；已有 Connection 但没有知识空间时显示“创建知识空间”。
4. 长期记忆卡片必须显示状态、范围、来源、更新时间、重要度/质量和过期策略。
5. 候选记忆显示确认和拒绝；冲突记忆必须同时展示旧值和新值；已生效记忆显示纠正和删除。
6. “清空我的记忆”必须二次确认，文案明确说明无法恢复；操作成功后重新从服务端加载，不只做本地清空。

## 12. 安全渲染

1. 来自用户、模型、Tool、Connection 和知识库的所有字符串在写入 HTML 前必须转义。
2. 不得将模型输出直接赋给 `innerHTML`。Markdown 渲染器必须使用白名单标签/属性并禁止任意 HTML、JavaScript URL 和内联事件。
3. 下载链接、图片 URL 和附件引用必须验证来源和协议，不得信任模型生成的本地路径。
4. 前端日志、Toast、对话卡片和错误堆栈不得输出 API Key、Token、密码或完整 DSN。
5. 退出登录或刷新 Token 失败后，必须清理内存中的敏感状态和附件预览 URL。

## 13. 响应式、可访问性和视觉一致性

1. 页面必须在常见桌面宽度和移动端宽度下验证，不得依赖超宽屏幕隐藏横向溢出。
2. 对话输入区、发送/中断按钮和主要任务状态必须始终在可见区域，不得因为长结果表格导致操作按钮滑出画面。
3. 表格优先在自身容器内横向滚动，不得撑宽整个对话页。超长 JSON/代码块必须换行或局部滚动。
4. 所有输入必须有可关联的 label，图标按钮必须有 `aria-label`，抽屉/对话框必须支持 Escape 关闭和合理的焦点返回。
5. 不得只用颜色表达排队、执行、成功和失败；必须同时有文字或图标。
6. 通用按钮、状态芯片、卡片、抽屉、表单间距和字号必须使用现有设计 Token/公共类，不在业务 HTML 中持续追加内联样式。
7. 用户启用减少动效时，打字效果、抽屉移动和加载动画必须遵循 `prefers-reduced-motion`。

## 14. 性能与请求管理

1. 页面只请求当前视图必要的数据，不在每次路由切换时重新加载全部配置和全部历史。
2. 搜索输入使用防抖或显式搜索按钮；旧请求必须可取消，避免慢响应覆盖新搜索结果。
3. 大列表必须分页、增量加载或虚拟化，不得将全部记忆、审计、知识片段和会话事件一次性渲染。
4. SSE/轮询更新应做局部 DOM 更新，不得每条 Token 都重新渲染整个会话列表。
5. 页面离开或组件销毁时必须取消 timer、AbortController、SSE 和事件监听，防止重复订阅和内存泄漏。

## 15. 前端改动必须的验收项

### 15.1 静态检查

1. `node --check frontend/app.js`。
2. HTML 中不存在重复 ID。
3. 新增 DOM 查询在元素可选时使用空值保护。
4. `git diff --check`。

### 15.2 角色矩阵

| 场景 | admin | approver | operator |
| --- | --- | --- | --- |
| 管理菜单 | 可见 | 仅审批 | 不可见 |
| 自己的会话 | 可见 | 可见 | 可见 |
| 其他用户会话 | 按管理 API | 不可见 | 不可见 |
| 自己的长期记忆 | 可见 | 可见 | 可见 |
| 租户记忆策略 | 可编辑 | 不可见 | 不可见 |
| 无权专业 Analyst | 按 Agent 边界 | 不可见 | 不可见 |

### 15.3 对话状态矩阵

1. 普通回答。
2. 单 Tool 调用。
3. 三个并行子任务，验证每个任务只有一张状态卡。
4. Tool 无权、参数验证失败和子任务部分失败。
5. 中断 queued 任务、中断 running 任务和检查点恢复。
6. Token 预算超限与大结果句柄。
7. SSE 断线重连，验证消息和任务不重复。

### 15.4 数据与错误矩阵

1. 空列表、单条、大列表和分页。
2. 401、403、404、409、422 和 500。
3. 用户切换、tenant 切换和 Token 过期。
4. 历史会话、新会话、删除会话和恢复会话。
5. 未配置模型、未配置 Connection、Connection 不可用和无业务 Tool 权限。

### 15.5 视觉与可访问性

1. 桌面窄屏、常见笔记本分辨率和移动端。
2. 长表格、长 JSON、长中文和长英文不破坏页面宽度。
3. 键盘完成登录、打开/关闭抽屉、选择模型、发送和中断。
4. 焦点可见，图标按钮有名称，状态不只依赖颜色。
5. 启用 `prefers-reduced-motion` 后主流程仍可正常操作。

## 16. 本次问题与规则对照

| 已出现的问题 | 对应必须规则 |
| --- | --- |
| 回答有序列表全部显示为 `1.` | 同一列表渲染为单个 `<ol>` |
| `queued` 和 `running` 显示为两个任务 | 根据 `task_id` 更新同一节点 |
| Tool 委派后页面提示完成，却没有最终答案 | 只以 turn 终态和已持久化答案标记完成 |
| 执行时只显示不可点击的“处理中” | 执行中提供中断，中断后提供继续 |
| 新增用户/权限组/规则表单常驻占据页面 | 使用按钮打开抽屉或对话框 |
| 权限规则明细可移动、权限组不能多选 Tool | 组上编辑多对多，明细只读 |
| 普通用户看到管理菜单 | 统一角色可见性和 API 权限双重保护 |
| 用户无 Tool 权限却仍看到对应专业 Analyst | Agent 列表基于服务端最终可用 Tool 过滤 |
| 切换用户后看到他人会话，修复后历史会话又消失 | 会话列表服务端按 owner 过滤，并处理历史数据迁移 |
| 前端轮询 `/v1/memories` 但后端未实现 | API 路由、前端调用和 API 测试同步交付 |
| 错误只显示“出错了” | 解析结构化错误并给出可操作建议 |
| 页面暴露内部表名和 Tool 参数 | 默认显示人类可读来源，技术详情按权限收起 |
| 没有 Key 的模型仍可调用 | 未配置模型不可选且发送前再校验 |
| 知识库只看到 Collection 和 Point 数 | 展示空间、分类、文档、片段、来源和处理状态 |
